A dated data note on whether a coding agent searches a memory server it is connected to. In our deployment, agents rarely searched the memory unless something told them to. The note tests three ways of telling a coding agent (Claude Code, claude-sonnet-5-5) when to search, and then checks whether the text that shipped changed ordinary use.

On a frozen bank of 36 tasks whose answer depends on a memory fact the prompt does not name, the agent's pass rate with the memory server alone was 0.065. A skill file raised it by 0.250 (95% CI 0.139 to 0.370). A text the memory server sends when the client connects (the MCP server instructions) raised it by 0.491 (0.352 to 0.630) but failed a pre-registered limit on false triggers, on tasks the memory does not cover. The same text with one sentence stating what the memory covers kept the gain (+0.463, 0.315 to 0.611) and brought false triggers within the limit. Before the main runs, a positive control found a ceiling set by the product: the search tool returned only the first 200 characters of each hit, and this was fixed. No tested text made the agent write to memory.

The scoped text shipped on 2026-11-08. In the owner's own sessions in the following week, 2 of 38 searched (0 of 269 before), which the pre-registered rule reads as no visible change. The operations agents on the same host, which never received the text, searched only during one weekly task whose answer needed the corpus. The note reports a gap between the evaluated effect and field use, not its cause.
